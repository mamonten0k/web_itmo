# ОРГАНИЗАЦИЯ ПРОЦЕССОВ ТЕСТИРОВАНИЯ

Для обеспечения качества и надежности веб-сервиса для оценки метрик Web-Vitals была разработана комплексная система тестирования, включающая различные типы тестов и интеграцию с процессами непрерывной интеграции (CI).

## Уровни тестирования

Система тестирования веб-сервиса включает следующие уровни:

1. **Статический анализ кода**
   - Использование ESLint для проверки качества кода и соблюдения стандартов кодирования
   - Автоматическая проверка типов с помощью TypeScript

2. **Модульное тестирование (Unit Testing)**
   - Тестирование отдельных компонентов и функций
   - Изоляция тестируемых модулей с помощью моков

3. **Интеграционное тестирование**
   - Проверка взаимодействия между различными компонентами системы
   - Тестирование API-интерфейсов

4. **Дымовое тестирование (Smoke Testing)**
   - Базовая проверка работоспособности основных функций системы
   - Быстрое выявление критических ошибок

## Инструменты тестирования

Для реализации системы тестирования были выбраны следующие инструменты:

### Jest

Jest был выбран в качестве основного фреймворка для тестирования по следующим причинам:

1. **Универсальность**: Jest подходит для тестирования как клиентской, так и серверной части приложения.
2. **Встроенные возможности**: Включает в себя средства для создания моков, снимков (snapshots) и измерения покрытия кода.
3. **Параллельное выполнение**: Тесты выполняются параллельно, что ускоряет процесс тестирования.
4. **Простота настройки**: Минимальная конфигурация для начала работы.

### ESLint

ESLint используется для статического анализа кода и обеспечивает:

1. **Соблюдение стандартов кодирования**: Единый стиль кода во всем проекте.
2. **Выявление потенциальных ошибок**: Обнаружение проблем до выполнения кода.
3. **Интеграцию с IDE**: Мгновенная обратная связь разработчикам.

## Дымовые тесты (Smoke Tests)

Для быстрой проверки работоспособности основных функций системы были реализованы дымовые тесты с использованием Jest. Эти тесты проверяют:

### Клиентская часть

1. **API-сервис**: Проверка корректности формирования запросов к серверу и обработки ответов.
   ```javascript
   test('getWebVitals makes correct fetch request', async () => {
     // Mock successful fetch response
     global.fetch.mockResolvedValueOnce({
       ok: true,
       json: async () => ({ data: { mockData: true } }),
     });

     // Test parameters
     const params = {
       url: 'https://example.com',
       modifiers: [types.Modifiers.ADD_LIGHTHOUSE_REPORT],
       throttleType: types.ThrottleType.NO_THROTTLE,
     };

     // Call the API service
     const result = await apiService.getWebVitals(params);

     // Verify the fetch call
     expect(global.fetch).toHaveBeenCalledTimes(1);
     expect(global.fetch).toHaveBeenCalledWith('/api/web-vitals', expect.objectContaining({
       method: 'POST',
       headers: expect.objectContaining({
         'Content-Type': 'application/json',
       }),
       body: JSON.stringify(params),
     }));

     // Verify the result
     expect(result).toEqual({ data: { mockData: true } });
   });
   ```

2. **Селекторы данных**: Проверка корректности выбора данных из DOM.
   ```javascript
   test('selectNetworkThrottlingType returns the value of the checked radio button', () => {
     // Mock DOM elements
     const mockRadioButton = {
       checked: true,
       value: '1', // ThrottleType.NO_THROTTLE
     };

     const mockDialog = {
       querySelectorAll: jest.fn().mockReturnValue([mockRadioButton]),
     };

     // Mock document.getElementById to return our mock dialog
     document.getElementById.mockReturnValue(mockDialog);

     // Call the selector
     const result = selectors.selectNetworkThrottlingType();

     // Verify the result
     expect(result).toBe('1');
     expect(document.getElementById).toHaveBeenCalledWith('dialog');
     expect(mockDialog.querySelectorAll).toHaveBeenCalledWith('[name="network"]');
   });
   ```

### Серверная часть

1. **Контроллер Web Vitals**: Проверка обработки запросов и формирования ответов.
   ```javascript
   test('webVitalsController processes request and returns data', async () => {
     // Call the controller
     await webVitalsController(mockRequest, mockResponse);

     // Verify Chrome was launched
     expect(startup.launchChrome).toHaveBeenCalled();

     // Verify a new page was created
     expect(mockBrowser.newPage).toHaveBeenCalled();

     // Verify the page was navigated to the URL
     expect(mockPage.goto).toHaveBeenCalledWith('https://example.com', expect.anything());

     // Verify the Lighthouse report was generated
     expect(modifiers.getLighthouseReport).toHaveBeenCalled();

     // Verify the response was sent
     expect(mockResponse.send).toHaveBeenCalledWith(expect.objectContaining({
       data: expect.objectContaining({
         lhr: expect.objectContaining({
           audits: expect.objectContaining({
             'first-contentful-paint': expect.anything(),
           }),
         }),
       }),
     }));
   });
   ```

### Интеграционные тесты

1. **Поток работы с Web Vitals**: Проверка взаимодействия между клиентом и сервером.
   ```javascript
   test('POST /api/web-vitals returns web vitals data', async () => {
     // Mock the Lighthouse report data
     const mockLighthouseData = {
       lhr: {
         audits: {
           'first-contentful-paint': { displayValue: '1.0 s' },
           'cumulative-layout-shift': { displayValue: '0' },
           'max-potential-fid': { displayValue: '100 ms' },
           'total-blocking-time': { displayValue: '0 ms' },
           'largest-contentful-paint': { displayValue: '1.5 s' },
           'interactive': { displayValue: '1.2 s' },
           'server-response-time': { displayValue: '0.1 s' },
         },
       },
     };

     // Mock the getLighthouseReport function
     modifiers.getLighthouseReport.mockResolvedValue(mockLighthouseData);

     // Make a request to the API
     const response = await request
       .post('/api/web-vitals')
       .send({
         url: 'https://example.com',
         modifiers: [types.Modifiers.ADD_LIGHTHOUSE_REPORT],
         throttleType: types.ThrottleType.NO_THROTTLE,
       })
       .expect(200);

     // Verify the response
     expect(response.body).toHaveProperty('data');
     expect(response.body.data).toHaveProperty('lhr');
     expect(response.body.data.lhr).toHaveProperty('audits');
   });
   ```

## Интеграция с CI/CD

Тесты интегрированы в процесс непрерывной интеграции (CI) с использованием GitHub Actions. Процесс тестирования автоматически запускается при каждом пуше в репозиторий и включает следующие этапы:

1. **Статический анализ кода**: Запуск ESLint для проверки качества кода.
2. **Модульное и интеграционное тестирование**: Запуск Jest для выполнения всех тестов.
3. **Анализ покрытия кода**: Генерация отчета о покрытии кода тестами.

Пример конфигурации GitHub Actions для запуска тестов:

```yaml
name: Science Paper CI/CD Pipeline

on:
  push:
    branches: [ main, master ]
    paths:
      - 'science_paper/**'
  pull_request:
    branches: [ main, master ]
    paths:
      - 'science_paper/**'

jobs:
  lint-and-test:
    name: Run Linter and Tests
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: ./science_paper
    steps:
      - name: Checkout code
        uses: actions/checkout@v3
      
      - name: Set up Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: ./science_paper/package-lock.json
      
      - name: Install dependencies
        run: npm ci
      
      - name: Run linter
        run: npm run lint
        
      - name: Run tests
        run: npm test
        
      - name: Generate test coverage
        run: npm run test:coverage
        
      - name: Archive test coverage
        uses: actions/upload-artifact@v3
        with:
          name: coverage-report
          path: ./science_paper/coverage
```

## Преимущества организации тестирования

Разработанная система тестирования обеспечивает следующие преимущества:

1. **Раннее выявление ошибок**: Автоматические тесты позволяют обнаруживать ошибки на ранних стадиях разработки.
2. **Повышение качества кода**: Статический анализ и тесты способствуют написанию более качественного и надежного кода.
3. **Упрощение рефакторинга**: Наличие тестов позволяет безопасно вносить изменения в код.
4. **Документирование поведения**: Тесты служат документацией, описывающей ожидаемое поведение системы.
5. **Автоматизация процессов**: Интеграция с CI/CD позволяет автоматизировать процесс тестирования и развертывания.

Таким образом, организация процессов тестирования веб-сервиса для оценки метрик Web-Vitals обеспечивает высокое качество и надежность разрабатываемого решения, что является важным аспектом практической значимости исследования.
